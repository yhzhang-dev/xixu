# 记账接口说明

服务端记账模块（`wiki.yuhang.xixu.ledger`）提供 `ledger_entry` 表的记账、查询与作废接口，统一前缀 `/api/ledger`。所有接口需先登录取得 Bearer token（见[登录功能本地运行.md](登录功能本地运行.md)），并在请求头 `Authorization: Bearer <token>` 中携带。

数据归属：所有读写都按当前登录用户（由 token 解析出的 `user_id`）限定，客户端无需也不能代传别人的 `user_id`。

## 记一笔账

`POST /api/ledger/entries`

请求体（JSON）：

```json
{
  "entryType": "EXPENSE",
  "amount": 12.50,
  "occurredOn": "2026-10-31",
  "occurredTime": "12:30:00",
  "categoryName": "吃饭",
  "channelName": "微信",
  "merchant": "某餐厅",
  "note": "午饭"
}
```

字段约束：`entryType` 为 `EXPENSE` / `INCOME`；`amount` 大于 0、最多 10 位整数 2 位小数；`occurredOn` 必填（`yyyy-MM-dd`）；`categoryName` 必填；其余 `occurredTime`、`channelName`、`merchant`、`note` 可空。此接口仅用于手动录入，服务端统一写入 `sourceType=手动`，不接收来源字段。

成功返回 `201`，响应体为完整记录（含 `id`、`status=1`、`createdAt`、`updatedAt`）。字段校验失败返回 `400`。

## 查询账目列表

`GET /api/ledger/entries?from=2026-10-01&to=2026-10-31&page=1&size=20`

`from` / `to` 为可选发生日期范围（含两端，`yyyy-MM-dd`），不传则查全部；开始日期晚于结束日期返回 `400`。`page` 默认 1，`size` 默认 20、最大 100。默认仅返回 `status=1`（有效）记录；传 `includeVoided=true` 可同时查看已作废记录及原因，`total` 也包含它们。按发生日期倒序。分页列表只用于展示，不用于计算总金额。

响应体：

```json
{
  "items": [
    { "id": 1, "userId": 1, "entryType": "EXPENSE", "amount": 12.50, "occurredOn": "2026-10-31", "categoryName": "吃饭", "status": 1 }
  ],
  "total": 1,
  "page": 1,
  "size": 20
}
```

## 查询单条账目

`GET /api/ledger/entries/{id}`

返回当前用户名下对应记录（含已作废）；不存在或不属于当前用户返回 `404`。

## 查询汇总

`GET /api/ledger/summary?from=2026-10-01&to=2026-10-31`

日期参数与列表相同。服务端从**全部有效记录**汇总，返回 `{ "count": 3, "expense": 56.50, "income": 100.00 }`。首页今日支出与手机月账本均使用此接口，不受列表分页限制。`count` 计收入和支出两种记录。

## 作废账目

`POST /api/ledger/entries/{id}/void`

请求体必填：`{ "reason": "重复录入" }`，原因须为 1–200 字非空文本。作废为软删除：`status` 置 0，写入 `voidReason` 与 `voidedAt`，记录不物理删除。成功返回 `200` 及更新后的记录；不存在返回 `404`；已作废（包括并发作废）返回 `409`。

> 说明：按[记账表设计](../database/02-记账表设计.md)，独立「更正留痕表」确定前暂不开放直接修改账目的接口；当前更正方式是「作废后重新录入」。直接编辑接口待变更记录表设计后补充。
