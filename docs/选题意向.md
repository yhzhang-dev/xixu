## 题目

**基于工具调用的个人生活数据管理与智能助理系统的设计与实现（暂定）。**

> 自审提示：当前代码尚未实现大模型调用与自然语言解析，仅有 1 个只读统计工具（`/api/assistant/tools/monthly-snapshot`）。按[论文大纲与审核意见](../thesis/00-论文大纲与审核意见.md)的评估，开题前需二选一：①把副标题收敛到已交付能力（例如「账务、日志与健康记录的统一建模与多端实现」）；②在第八学期第 7 周前补齐「一句话记账」的最小闭环。建议取①。

## 选题来源

已有本地原型以微信与 DeepSeek Harness 为交互入口，通过 Python 脚本、Markdown 和 JSONL 串起记账、课表、日志和附件归档。原型已用于日常记录，但依赖电脑和第三方聊天入口，缺少数据库、独立移动端及 Web 管理界面。毕业设计拟将其中经过实际使用验证的需求重新实现为独立系统。原型可作需求和数据迁移参考，不作为新系统运行时依赖。

## 首期范围

| 层次 | 内容 | 现状 |
|---|---|---|
| 核心业务 | 记账、每日日志与结构化健身训练、体重与睡眠记录 | 记账已联调；日志、身体模块代码与页面就绪，待联调 |

| 智能助理 | 受限只读统计工具；自然语言草稿生成 | 只读工具已实现；草稿生成规划中 |

Web 与 Android 共用 Spring Boot 接口及同一份数据，不依赖微信或 DeepSeek Harness。先完成手动录入、结构化日志与查询，再加入受控工具调用；模型只能生成草稿或请求查询，写入须经用户确认。首期不以离线同步、通用 Agent 平台、向量检索、微服务或云端对象存储为交付目标。

## 暂定技术路线

- Android：uni-app（Vue 3），以真机运行和安装包演示；若学校要求原生 Android，改为 Kotlin 客户端。
- Web：Vue 3 + Vite（当前未引入 UI 组件库与图表库）。
- 服务端：Java 17 + Spring Boot 4.1，使用 JDBC（`JdbcTemplate`），自研随机令牌鉴权（非 JWT）。
- 数据库：MySQL 8.4；附件文件与数据库元数据分别保存。
- 开发与演示：先在本机完成端到端联调，再部署 Web 静态资源、Spring Boot 服务与数据库。
