# 本科毕业设计选题意向（当前版）

> 更新：2026-10-30。此文件是待指导教师确认的工作方案，不代表功能和数据库已经定稿。旧版保存在 `选题意向-初稿-2026-10-30.md`。

## 题目

个人生活数据管理系统的设计与实现。

## 选题来源

已有本地原型以微信与 DeepSeek Harness 为交互入口，通过 Python 脚本、Markdown 和 JSONL 串起记账、课表、日志和附件归档。原型已用于日常记录，但依赖电脑和第三方聊天入口，缺少数据库、独立移动端及 Web 管理界面。毕业设计拟将其中经过实际使用验证的需求重新实现为独立系统。原型可作需求和数据迁移参考，不作为新系统运行时依赖。

## 首期范围

| 层次 | 内容 |
|---|---|
| 核心业务 | 记账、课表与日程、每日日志、附件上传与关联 |
| 基础能力 | 登录、增删改查、查询筛选、基础统计、基础提醒 |
| 重点增强 | 一句话记账；解析失败时允许手动确认或修改 |
| 后续扩展 | 图片文字识别、复杂统计、历史数据迁移 |

Android 客户端和 Web 管理端共用 Spring Boot 接口及同一份数据，应能独立完成核心操作，不依赖微信或 DeepSeek Harness。Web 端最终部署在云服务器上，供用户管理自己的数据，也提供必要的系统账号管理。先完成手动录入与查询，再加入智能录入。首期不以离线同步、通用 Agent、向量检索、微服务或云端对象存储为交付目标。

## 暂定技术路线

- Android：uni-app（Vue 3），以真机运行和安装包演示；若学校要求原生 Android，改为 Kotlin 客户端。
- Web：Vue 3 + Vite + Element Plus。
- 服务端：Java 17 + Spring Boot，向两个客户端提供 REST API。
- 数据库：MySQL 8.4；附件文件与数据库元数据分别保存。
- 开发与演示：先在本机完成端到端联调，再部署 Web 静态资源、Spring Boot 服务与数据库；云服务和域名配置待本机闭环完成后确定。

## 工作量估算

以单人开发、已有 Vue 与 Spring Boot 基础为前提，核心版暂估 12～16 周、约 250～350 小时；包含需求与数据库设计、服务端、两端界面、联调测试和论文材料。表数暂估 10～12 张，下一步通过用例和 ER 图确定，不按数量凑表。智能录入与拍照识别的完成度取决于核心功能进度。
