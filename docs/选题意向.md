# 本科毕业设计选题意向（当前版）

> 更新：2026-11-01。根据指导教师对工作量的反馈调整方向，仍待教师确认；不代表功能和数据库已经定稿。旧版保存在 `选题意向-初稿-2026-10-30.md`。

## 题目

基于工具调用的个人生活数据管理与智能助理系统的设计与实现（暂定）。

## 选题来源

已有本地原型以微信与 DeepSeek Harness 为交互入口，通过 Python 脚本、Markdown 和 JSONL 串起记账、课表、日志和附件归档。原型已用于日常记录，但依赖电脑和第三方聊天入口，缺少数据库、独立移动端及 Web 管理界面。毕业设计拟将其中经过实际使用验证的需求重新实现为独立系统。原型可作需求和数据迁移参考，不作为新系统运行时依赖。

## 首期范围

| 层次 | 内容 |
|---|---|
| 核心业务 | 记账、课表与日程、每日日志及结构化健身训练、附件上传与关联 |
| 基础能力 | 登录、增删改查、查询筛选、统计、提醒；Web 与 Android 共用服务端数据 |
| 智能助理重点 | 自然语言生成记账或训练草稿，经用户核对后保存；通过受限查询工具回答跨模块统计问题 |
| 验证重点 | 设计固定测试样例，衡量字段识别、工具选择和任务完成情况，保留错误案例 |
| 后续扩展 | 图片文字识别、知识检索、历史数据迁移 |

Android 客户端和 Web 管理端共用 Spring Boot 接口及同一份数据，不依赖微信或 DeepSeek Harness。Web 端最终部署在云服务器上。先完成手动录入、结构化日志与查询，再加入受控工具调用；模型只能生成草稿或请求查询，写入须经用户确认。首期不以离线同步、通用 Agent 平台、向量检索、微服务或云端对象存储为交付目标。

## 暂定技术路线

- Android：uni-app（Vue 3），以真机运行和安装包演示；若学校要求原生 Android，改为 Kotlin 客户端。
- Web：Vue 3 + Vite + Element Plus。
- 服务端：Java 17 + Spring Boot，向两个客户端提供 REST API。
- 数据库：MySQL 8.4；附件文件与数据库元数据分别保存。
- 开发与演示：先在本机完成端到端联调，再部署 Web 静态资源、Spring Boot 服务与数据库；云服务和域名配置待本机闭环完成后确定。

## 工作量估算

工作量按完整业务流程、两端联调、Agent 工具调用和评估测试核算。旧版 10～12 张表及工时估计已不适用于调整后的范围；待用例和 ER 图确定后重新估算，不按数量凑表。当前已验证登录和跨端记账；日志与训练的首版代码已写，尚未建表联调；Agent 尚未实现。
