# 日志与训练记录（第一版）

此模块已有服务端、Web 和 Android 页面。用户已报告旧版表迁移和 184 条样本导入成功，并在 Web 页面确认类别、时间、备注可见；手动保存及 Android 端查看仍待验证。下述导入脚本会在两张日志表都不存在时执行 [`database/05-日志与训练记录.sql`](../database/05-日志与训练记录.sql)；若已按旧版 05 脚本建表，则自动执行 [06 迁移](../database/06-日志真实样本字段迁移.sql)。不要在已有表上手动重复执行 05。

## 数据结构

- `life_log_entry`：所属用户、发生日期、`NOTE` 或 `WORKOUT`、原始类别、原始时间文字、标题、正文、备注、来源及录入时间。一日可以有多条记录。`source_ref` 用于重复导入时识别同一来源行。
- `workout_set`：仅供训练记录使用；每组保存项目名称、次数、重量（kg）、时长（秒）。次数和时长至少有一个；没有提供的数值保持 `NULL`。
- 新增日志与其组次在同一事务中写入。所有查询按已登录用户的 ID 限定。

## 接口

所有接口需要 `Authorization: Bearer <token>`。

| 方法与路径 | 用途 |
|---|---|
| `POST /api/logs` | 新增文字日志或训练记录 |
| `GET /api/logs?type=WORKOUT&page=1&size=20` | 分页查询；`type`、`from`、`to` 可选 |
| `GET /api/logs/{id}` | 查询本人单条记录及组次 |
| `GET /api/assistant/tools/monthly-snapshot?month=2026-11` | 只读汇总本人该月训练次数、有效账目数、收入与支出 |

训练记录请求示例（仅示意，不会自动写入）：

```json
{
  "entryType": "WORKOUT",
  "occurredOn": "2026-11-01",
  "title": "胸部训练",
  "content": "卧推四组，每组八次。",
  "sets": [
    { "exerciseName": "卧推", "repetitions": 8, "weightKg": 40, "durationSeconds": null },
    { "exerciseName": "卧推", "repetitions": 8, "weightKg": 40, "durationSeconds": null }
  ]
}
```

示例只列出两组；实际记录四组时应提交四个组次对象。普通文字日志使用 `entryType: "NOTE"`，`sets` 传空数组。

## 当前边界

第一版支持手动新增、查询和一个跨模块只读工具。Web 页面可复制训练组次并按月筛选；Android 已加入日志与训练的录入和按月回看页面，**已在真机确认页面可打开，尚未创建真实记录验证保存**。目前还没有修改、作废或附件关联；**模型接入及自动工具选择尚未实现**。后续 Agent 应先生成可编辑草稿，由用户确认后调用同一保存接口，避免模型直接写库。正式测试前还需完成真实 MySQL 联调和跨用户访问验证。

## 本地真实样本导入

`E:\dsh-im\log` 中每日 Markdown 的「生活记录」表可作为样本。先在 `server` 目录运行：

```powershell
.\import-dsh-logs-local.ps1 -PreviewOnly
.\import-dsh-logs-local.ps1 -AppUsername Admin1031
```

第二条命令在本机提示输入 MySQL 凭据，写入 `xixu_dev` 对应账号。两张日志表都不存在时自动建表；旧版表会自动迁移。脚本不会修改原日志，不会生成含私人内容的 SQL 文件；源文件未变化时可重复运行，已导入的来源行会跳过。它是一次性样本导入，不会持续同步原文件的后续修改。完成后重启后端，刷新 Web 或重新运行 Android，选 **2026 年 10 月**查看。当前样本为 10 天、184 条，导入前脚本会重新计数，实际数量以当时的原日志为准。

所有原始表格行暂存为 `NOTE`，包括类别为「运动」的行；原文可能是计划、休息或区间次数，不能直接算作完成训练，也不能凭描述补造 `workout_set`。类别为「消费」「日程」的行仅作日志样本，不写入记账和日程表，避免统计重复。完整日记正文、附件文件、账本原文件均未导入。

真实样本暴露出两个下一步设计问题：一是 `NOTE/WORKOUT` 只表达记录形式，不足以承载多类别筛选；后续可为类别增加受控字典或映射。二是训练的计划、完成状态和区间数值需要单独建模或保留原文，现有 `workout_set` 仅适用于明确完成且数值确定的组次。先核对页面显示和实际查询，再决定字段迁移，不按样本猜造数字。
