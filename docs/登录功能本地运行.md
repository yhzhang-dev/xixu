# 登录功能本地运行

当前实现：Spring Boot 4.1.2 + MySQL 8.4，用户名/密码校验、24 小时随机令牌、`/me`、退出登录；uni-app 真机通过 USB ADB 反向端口连接本机后端。2026-10-31 用户报告已看到「初始管理员账号已创建」，并运行本地自检确认真实账号登录、`/me` 查询及退出后令牌失效；本工作区已验证 `/api/health` 返回 200、未登录 `/api/auth/me` 返回 401。最新版 App 已在 USB 真机启动，用户确认登录后进入首页并显示「早上好，Admin1031」。

## 2026-11-01 登录会话增强迁移

当前 `auth_session` 的实际建表语句已经由用户提供：`expires_at` 为非空列，`token_hash` 有唯一索引。服务端原本就检查 24 小时有效期；“没有过期时间”“没有 token 索引”不适用于当前库。新版本补充登录时的 `user_agent`、直接连接后端的 `ip_address`、最近使用时间，最多保留同一账号 **5 个有效会话**；成功登录时清理该账号过期或已注销超过 30 天的会话。会话和 `app_user.last_login_at` 的新写入时间统一使用 MySQL 的 `UTC_TIMESTAMP(3)`。旧会话的历史时间可能混有不同口径，迁移不猜测也不改写它们。

升级已有数据库时，按顺序操作：

1. 在运行后端的终端按 `Ctrl+C`，确认旧服务已退出。
2. 在 MySQL 客户端执行 [`database/07-登录会话增强迁移.sql`](../database/07-登录会话增强迁移.sql) **一次**。脚本会使所有现有令牌失效，Web 和手机需要重新登录；不会删除用户或记账、日志数据。
3. 用普通命令 `.\start-local.ps1` 启动新版后端，不加 `-CreateAdmin`。重新登录 Web 和手机。
4. 检查脚本末尾 `active_sessions_after_migration = 0`。新登录后可用 `SELECT COUNT(*) FROM auth_session WHERE user_id = 1 AND revoked_at IS NULL AND expires_at > UTC_TIMESTAMP(3);` 只读核对有效会话数，不要发送 `token_hash` 或原始令牌。

新环境只执行更新后的 [03 建表脚本](../database/03-登录会话表.sql)，不执行 07。`ip_address` 取后端直连地址：本地 ADB reverse 或反向代理下可能只是 `127.0.0.1` 或代理地址；部署时若需要真实客户端 IP，应先配置可信代理链，不能直接信任任意 `X-Forwarded-For`。设备管理页面和异常登录提醒尚未实现。

2026-11-01，用户报告 07 迁移执行成功，升级后 Web 账号可重新登录；本工作区确认新版服务监听 18080，`/api/health` 返回 200，服务端 19 项测试通过。用户随后执行只读查询：当前账号有 1 个有效会话，`user_agent`、`ip_address`、`last_used_at` 均非空，创建至过期为 86400 秒。5 个会话上限和 30 天清理逻辑尚未通过连续登录做真实数据库压力验证。

本机 8080 端口被 Steam 的 Web Helper 占用，因此汐序本地服务改用 **18080**；启动脚本会在询问密码前检查端口。

## 日常启动（数据库和管理员已创建）

MySQL 的 `MySQL84` 服务一般随 Windows 自动启动。用 `Get-Service MySQL84` 查看；若为 `Stopped`，在管理员 PowerShell 运行 `Start-Service MySQL84`。然后打开两个终端。

终端一启动后端，按提示输入 MySQL 用户名和密码，并保持运行：

```powershell
cd E:\graduation-project\server
.\start-local.ps1
```

终端二启动 Web：

```powershell
cd E:\graduation-project\admin
npm run dev
```

打开 <http://127.0.0.1:5173/>。后端启动时应看到 `Started XixuServerApplication`；若提示 18080 端口被占用，先确认是否已有汐序服务在运行。已有账号时不要加 `-CreateAdmin`，也不要重新执行建表脚本。关闭时在两个终端分别按 `Ctrl+C`；MySQL 服务可保持运行。

## 1. 建登录会话表（仅首次安装）

在数据库客户端选中 `xixu_dev`，运行 [`database/03-登录会话表.sql`](../database/03-登录会话表.sql)。MySQL 命令行可执行：

```sql
USE xixu_dev;
SOURCE E:/graduation-project/database/03-登录会话表.sql
SHOW TABLES;
```

应看到原有的 `app_user` 和新的 `auth_session`。如果表已经存在，先不要重复运行或删除。

## 2. 在 VS Code 中启动后端

打开 `E:\graduation-project\server`，终端运行：

```powershell
.\start-local.ps1 -CreateAdmin
```

第一次运行输入 MySQL 用户名（直接回车是 root）、MySQL 密码、要创建的管理员用户名和至少 12 位的管理员密码。密码输入不显示，也不写入项目。此命令**只用于用户表为空时**；若已有用户，则不要加 `-CreateAdmin`。服务端显示 `Started XixuServerApplication`，随后显示「初始管理员账号已创建」才算初始化完成。保留终端运行。

以后启动只执行：

```powershell
.\start-local.ps1
```

本地首次联调暂用 root 连接开发库；完成验证后再建立仅有 `xixu_dev` 所需权限的应用账号。不要把 root 密码写入 `application.properties`、`.env` 或聊天。

脚本已支持免交互启动：先在终端设置 `$env:XIXU_DB_USER`（可选，默认 root）和 `$env:XIXU_DB_PASSWORD`，再运行 `./start-local.ps1` 即可跳过密码提示（密码仍只存在当前会话环境，不落盘）。

## 3. 检查后端接口

在另一个 PowerShell 终端运行：

```powershell
Invoke-RestMethod http://127.0.0.1:18080/api/health
```

应显示 `status: ok`。`/api/auth/login` 接收 `username` 和 `password`；成功返回 `token`、`expiresInSeconds`、`user`，失败返回 401；`/api/auth/me` 需带 `Authorization: Bearer <token>`。请不要把真实 token 或密码发到聊天。

创建初始管理员后，可在 `server/` 的另一个终端运行 `./test-login-local.ps1`，输入账号和密码。脚本只显示登录、身份查询和退出登录的结果，不打印密码或令牌。

若登录脚本和 Web 登录都返回 401，且 `app_user.status=1`，可运行 `server/diagnose-admin-local.ps1`。默认模式会在本机提示 MySQL 凭据及该账号密码，只读查询 `app_user` 并用与服务端相同的 `BCryptPasswordEncoder` 核对，显示数据库标识、`password=MATCH` 或 `MISMATCH` 以及哈希指纹，不打印密码及完整哈希。`MISMATCH` 表示当前输入与该库的密码哈希不符；`MATCH` 而 API 仍返回 401 时，可加 `-CompareApi` 让脚本以**同一份输入**再调用一次登录接口并报告 HTTP 状态。该选项若登录成功，会创建后立即注销一次会话并更新最后登录时间。不要再次运行 `-CreateAdmin` 覆盖已有账号，也不要向聊天发送密码或完整哈希。

## 4. 让 USB 真机访问本机

保持 USB 调试与手机连接，在 PowerShell 运行：

```powershell
& 'C:\Users\astroz\AppData\Local\Android\Sdk\platform-tools\adb.exe' reverse tcp:18080 tcp:18080
```

当前 uni-app 开发地址为 `http://127.0.0.1:18080`；反向端口在手机重新连接后可能需要重新执行。用 HBuilderX「运行到 Android App 基座」重新运行 `android/`，在登录页输入刚创建的账号密码。登录成功进入首页并显示用户名；底部可退出登录。记账已接入真实接口，日志样本已导入本地库，日程仍待开发。

此 HTTP 地址只用于 USB 本地调试。云端部署前改为 HTTPS API 域名，并使用独立的数据库账号。
