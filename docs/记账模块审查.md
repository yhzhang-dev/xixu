# 记账模块审查（2026-10-31）

本次检查范围：`server` 的记账接口与表设计、`admin` 记账页面、`android` 记一笔及账本页面。未读取或迁移 `E:\dsh-im` 中的个人账目。

## 已修复

| 问题 | 处理 |
|---|---|
| 手机首页原来只取最多 100 笔并在客户端累加，超过 100 笔会少算 | 新增服务端 `/api/ledger/summary`，由数据库汇总全部有效记录；首页和月账本都使用汇总接口 |
| 日期起止颠倒仍发查询 | 服务端返回 400，Web 端先提示输入错误 |
| 同一笔并发作废，第二次更新 0 行仍被当作成功 | 检查更新行数；并发或重复作废返回 409 |
| 作废缺少原因，无法解释更正 | 作废原因改为必填，Web 端提供确认弹窗和输入框 |
| 作废记录虽然留在数据库，却无法在列表中回看 | Web 端新增“显示已作废”，可查看原因；汇总仍只计有效账目 |
| Web 端没有明确金额格式，手机端可重复点击保存 | 两端限制金额为正数、最多 10 位整数和 2 位小数；手机保存后阻止再次提交 |
| 手机只能看首页的几条今日账 | 新增按月查看、翻页加载的账本页面；首页可进入 |
| 服务端允许客户端自称任意账目来源 | 手动录入接口由服务端固定写入 `sourceType=手动` |

## 尚需完成或确认

1. **请求超时后的重复账风险**：客户端提交时已阻止连续点击，但服务器入库成功、响应在网络中丢失时，用户重试仍可能产生重复记录。下一步可给新增接口加幂等键和数据库唯一约束；目前遇到超时，应先在账本核对再重试。
2. **更正能力**：目前没有直接编辑账目；通过“带原因作废 → 重新录入”更正。Web 端可作废，手机账本暂为只读；独立更正留痕表尚未设计。
3. **真实环境部署**：Android 仍使用 `127.0.0.1:18080` 与 USB `adb reverse`，Web 开发服务器通过 Vite 代理。离开本地开发环境后需改为 HTTPS 域名，并配置部署地址、权限与备份。
4. **原型数据与增强功能**：`dsh-im` 文件账本未迁移；一句话记账、截图识别、凭据关联、退款与转账口径尚未实现。当前 `ledger_entry` 仅表示人民币收入或支出，退款若简单计为收入会影响收入统计，需要另定口径。
