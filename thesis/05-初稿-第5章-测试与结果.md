第 5 章 系统测试与结果分析

本章说明对前述实现的验证方式与结果。测试分三个层次：服务层单元测试用于锁定业务规则，接口联调脚本用于验证真实数据库下的完整链路，跨端人工验收用于确认两个客户端与服务端的数据一致。三层测试的结论分别给出，并单独说明尚未覆盖的部分。

5.1 测试环境与方法

5.1.1 测试环境

测试在单台开发机上完成。操作系统为 Windows，运行环境为 JDK 17（Temurin 17.0.19）、Node.js 24.18.0 与 MySQL 8.4.13；构建工具为 Maven Wrapper 3.10.0 与 npm；Android 端由 HBuilderX 构建并运行到真机，通过端口反向转发把手机上的本地地址映射到开发机的一万八千零八十端口。数据库为本地的开发库，服务端以单实例方式启动。测试数据包括手工构造的边界数据与从既有原型导入的一百八十四条真实样本。

5.1.2 测试方法

单元测试采用模拟仓储的方式，只实例化服务类，替换其依赖的仓储对象，因此测试过程不启动 Spring 上下文、不连接数据库。这种写法的优点是执行快、失败定位准，缺点是无法验证 SQL 是否正确，这一部分由第二层测试承担。接口联调脚本以幂等方式对运行中的服务端发起真实请求，并在每一步断言状态码与关键字段，覆盖“新增、汇总、列表、单条、作废、再次汇总、查看留痕、重复作废”的完整序列。跨端人工验收则由使用者在真机上完成录入，再在浏览器中查看与更正，结果以文档形式记录。

5.2 单元测试

5.2.1 用例分布

服务端共有五个测试类、二十三个测试方法。记账服务十个，认证服务三个，日志服务四个，健康服务四个，智能工具两个。此外，样本导入工具另有两个基于单元测试框架的用例，用于验证解析与输出行为，合计二十五个自动化用例。（此处插入表 5.1 测试用例分布与覆盖点。）

5.2.2 认证模块

认证模块的用例集中在校验顺序与副作用上。第一个用例验证正确密码登录时的完整行为：返回的令牌长度为四十三、过期时间为二十四小时的秒数、写入会话表的摘要是六十四位十六进制且与令牌本身不相等，并断言会话数量控制与过期清理被调用。第二个用例验证密码错误与账号停用两种情形都不创建会话，且会话仓储完全没有被调用。第三个用例验证格式非法的令牌在进入数据库查询之前即被拒绝，同样断言会话仓储零调用。这三个用例实际上锁定了一条安全规则：不可信的输入不应产生数据访问。

5.2.3 记账模块

记账模块的十个用例覆盖四类规则。第一类是归属规则：同一主键在不同用户下查询，只有记录所属用户能取到结果。第二类是参数归一规则：页码与每页条数越界时被钳制到边界值，缺省日期范围被补齐为全区间，日期起止颠倒时直接抛出状态异常且仓储零调用。第三类是统计规则：汇总方法只调用汇总语句，从不调用分页查询，从调用关系上保证了统计与分页无关。第四类是状态冲突规则：作废成功时状态由一变为零；记录已作废时不执行更新；记录不存在时返回未找到；受影响行数为零时判定为并发冲突。第四类中的最后一个用例是本模块最有价值的用例，它模拟了“查询时仍然有效、更新时已被他人作废”的时间窗口，正对应第 4 章说明的第三层校验。

5.2.4 日志与健康模块

日志模块的四个用例验证记录形式与数据形态的绑定关系：训练记录不带任何组次时被拒绝，训练记录带一组但次数与时长为空时被拒绝，文字记录携带组次时被拒绝，正常训练记录写入组次并返回服务端生成的记录。健康模块的四个用例验证三件事：体重记录不能全部为空；睡眠分段之和不得超过总时长；查询区间越界时被拒绝，包括起止颠倒与跨度超过一年两种情形。

5.2.5 智能工具与导入工具

智能工具的两个用例验证跨模块汇总的口径：汇总结果同时取自记账与日志两个仓储，且月份参数非法时不查询任何数据。导入工具的两个用例验证解析与输出：类别为“运动”且次数为区间值的原文被保留为文字记录而不被拆成训练组次，输出的 SQL 不含原始正文且使用冲突时忽略的写法规避重复；字段数不符的畸形行在生成 SQL 之前即被拒绝。第二个用例中的“不含原始正文”这一断言，针对的是导入过程中的隐私风险，属于功能性断言之外的附加约束。

5.3 接口与跨端联调

5.3.1 登录与身份链路

登录联调脚本以交互方式接收账号密码，不把凭据写入文件，并在结束时清空相关变量。脚本依次验证四个步骤：正确登录返回 200、携带令牌查询当前用户返回 200、退出登录返回 204、退出后用同一令牌再查询返回 401。该脚本已实际运行通过，确认安全配置的放行规则、过滤器的令牌还原与退出后的即时失效三者一致。错误密码与格式非法令牌两种情形不在该脚本内，由 5.2.2 的单元用例覆盖。

5.3.2 记账的完整链路

记账联调脚本按顺序执行健康检查、登录、作废前汇总、新增一笔十二元五角的测试支出、新增后汇总、列表查询、单条查询、带原因作废、作废后汇总、查看已作废记录、重复作废、退出登录十二步；脚本开头即提示“会新增一笔测试支出并立即作废，数据库保留一条已作废记录”，并在中断时提供清理分支。实际运行的记录显示：新增返回的记录编号为二，新增后汇总的笔数与金额同步变化，作废后汇总只计有效记录，重复作废返回状态码 409。测试记录随后以已作废状态保留在库中，成为“留痕可见”的实物证据。

在此之后，使用者完成了跨端流程验证：在手机上新增一笔金额为零点零一元的账目，在浏览器中查询到该记录并执行带原因的作废，回到手机上确认列表状态同步。该流程验证了三个客户端共用同一份数据这一核心设计目标。

5.3.3 日志样本导入与回看

样本导入分两步执行，先以只读方式预览计数，再写入指定账号。导入结果为十天、一百八十四条记录，导入后服务端重启，在浏览器中选择对应月份可以看到类别、时间与备注三列，说明迁移后的字段映射正确。需要说明的是，这一步验证的是“导入的字段能被正确读出”，不是“日志的手工新增与修改已经完整可用”。

5.3.4 构建与回归

服务端执行测试任务通过，Web 端执行生产构建通过，Android 端三个部分的页面模板可正常编译并在真机打开。三项构建检查在每次改动后重复执行，作为最基本的回归手段。

5.4 结果分析与不足

5.4.1 已验证的能力

综合三层测试，可以得到以下结论。业务规则层面，认证的校验顺序、记账的归属与状态冲突、日志的形式与数据绑定、健康的数值一致性均有用例锁定，且这些用例在仓储层被替换为模拟对象时仍能通过，说明规则确实写在服务层而不是数据库约束里。链路层面，“手机新增、Web 查看、Web 作废”这条主流程已经在真实数据库中走通，统计口径在作废前后的变化符合预期。数据层面，一百八十四条真实样本的导入与回看证明字段迁移方案可用。

5.4.2 尚未覆盖的部分

必须明确指出以下四类验证缺口，它们也是本系统与“可用于生产”之间的差距。

其一，SQL 与控制器未被自动化测试覆盖。单元测试替换掉了仓储，因此手写 SQL 的正确性只由联调脚本间接验证；控制器的状态码映射、参数绑定与异常通知同样没有自动化用例。这意味着修改 SQL 或调整映射时，回归依赖人工脚本。

其二，并发冲突是模拟而非真实并发。受影响的用例把更新行数直接设定为零，验证了服务层对冲突的判定逻辑，但没有启动两个线程同时作废同一笔账目。真实并发下的隔离级别行为、锁等待时间与死锁可能都未被观察到。

其三，跨用户越权只有服务层用例，没有接口级用例。现有用例证明服务层的查询带有用户限定，但没有对真实接口发起“用甲用户令牌访问乙用户记录”的请求并断言 404。这一条在答辩时很可能被问到。

其四，性能与容量未测试。未测量接口在数千条记录下的响应时间，也未测试连接池上限、慢查询与并发登录时的会话表锁竞争。

5.4.3 改进方向

针对上述缺口，后续应补充三类测试：一是对控制器使用切片测试，断言每个接口的状态码与响应体结构；二是增加集成测试，用真实数据库验证 SQL 与事务；三是编写并发与越权的接口级用例。此外，导入工具的两个用例目前需手动执行，应纳入统一的测试入口。

5.5 本章小结

本章按单元测试、接口联调、跨端验收三个层次说明了系统的验证情况。二十五个自动化用例覆盖了认证、记账、日志、健康与跨模块汇总的主要业务规则，其中并发窗口、记录形式与数据绑定、睡眠数值一致性三类用例针对性较强；联调脚本在真实数据库上验证了记账的完整生命周期与令牌的即时失效；跨端验收确认了两个客户端共享同一份数据。同时，本章明确列出了 SQL 未覆盖、并发为模拟、越权缺接口级用例、性能未测四项缺口，这些内容构成后续工作的直接输入，也应作为论文“不足与展望”的事实依据。
