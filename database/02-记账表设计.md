## 一笔账是什么

一条记录表示一个用户的一笔支出或收入。金额恒为正数，由 `entry_type` 区分方向；退款按收入或原账作废处理。业务发生日期与录入时间分开，用户没提供具体发生时间时留空。

## 建议的核心字段

| 字段 | 建议类型 | 说明 |
|---|---|---|
| `id` | `BIGINT UNSIGNED` | 主键，自增 |
| `user_id` | `BIGINT UNSIGNED` | 所属用户，关联 `app_user.id` |
| `entry_type` | `VARCHAR(8)` | `EXPENSE` / `INCOME` |
| `amount` | `DECIMAL(12,2)` | 正数，人民币金额；不用浮点数 |
| `occurred_on` | `DATE` | 实际发生日期 |
| `occurred_time` | `TIME`，可空 | 实际发生时间；未知就留空 |
| `category_name` | `VARCHAR(50)` | 吃饭、交通等；初版先用文字分类 |
| `channel_name` | `VARCHAR(30)`，可空 | 微信、支付宝、现金等 |
| `merchant` | `VARCHAR(100)`，可空 | 商家或收款方 |
| `note` | `VARCHAR(500)`，可空 | 备注 |
| `source_type` | `VARCHAR(20)`，可空 | 手动、自述、截图、账单等来源 |
| `status` | `TINYINT UNSIGNED` | 1 有效、0 作废；作废不直接删除 |
| `void_reason` / `voided_at` | 文字 / 时间，可空 | 作废原因与时间 |
| `created_at` / `updated_at` | `DATETIME(3)` | 录入与修改时间 |

查询通常按 `user_id` + `occurred_on` 的月份范围筛选，所以需要组合索引。`user_id` 作为外键，删除用户时先限制删除，避免误删账目。所有查询由服务端根据当前登录用户确定 `user_id`。

## 待设计的关联

- 截图凭据：等附件表确定后，用关联表或外键连到归档附件，不在此表保存本机绝对路径。

- 分类管理：初版可用文字字段；若需要用户自定义分类，再增加分类表与关联字段。
